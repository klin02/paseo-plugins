Web GPT Notifier shows ChatGPT task activity in Paseo's desktop browser, sends native notifications when replies finish, and can send completion notices to ntfy. Computer and phone subscribers can receive the same notice. It does not use a coding agent or call an AI API.

Allow Paseo notifications in your operating system. Native notifications and activity work without ntfy. To also use ntfy, open the plugin's settings on the connected host, enter your server and topic, and save. An access token is optional for servers that require one. The destination and token are stored in that host's local Paseo settings; they are not included in the plugin source. Use the test action to check delivery.

Requires Paseo Desktop and daemon 0.14.x or 0.15.x. Keep Desktop running with the ChatGPT tabs open. Resident tabs in other workspaces of the same window are monitored too. External Chrome or Edge tabs, unopened conversations, and mobile browsers are outside its monitoring scope.

The Web GPT sidebar shows conversation titles, running spinners, and completed, stopped, or error states. Completed replies have green checks in the conversation list; when no reply is running, the sidebar and workspace header also indicate completion. Starting a reply updates activity without sending a notification. Workspaces with local ChatGPT tabs get a GPT header indicator with the running count. Click a task or native notification to return to its original tab. Each computer shows its own local tasks and notifications; ntfy delivery is deduplicated by the shared daemon. Closing a tab removes its activity row. Activity starts afresh when the plugin reloads.

The plugin observes generation controls and waits for the answer to stop changing. Existing completed history is ignored. Manual stops and visible generation errors suppress success notices. This is a page-based heuristic, so ChatGPT interface changes can require an update. It uses internal Paseo Desktop interfaces for webviews, native notifications, and tab focus and limits compatibility to 0.14.x and 0.15.x.

Only the conversation title, link, and a fixed completion message are sent through the host to ntfy. Reply text is hashed inside the browser page and is not forwarded. A bounded local list of delivered identifiers prevents repeat notices across clients and restarts. Transient delivery failures are retried; a lost HTTP acknowledgement can still cause a duplicate. The plugin shows monitor presence, whether page samples are updating, and delivery status in its settings.
